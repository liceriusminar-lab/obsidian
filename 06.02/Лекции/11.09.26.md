# DevOps: принципы, жизненный цикл, инструменты

> [!note] Связанная лекция
> Определение DevOps — в лекции [[06.02/Лекции/04.09.26|04.09.26]].

## 1. Какую проблему решает DevOps

Разработка и эксплуатация хотят разного:

| | Разработчики | Эксплуатация (администраторы) |
|---|---|---|
| **Чего хотят** | как можно чаще выпускать новые функции и изменения | стабильности: любое изменение — риск остановки сервера |
| **Метрика успеха** | скорость и инновации | надёжность и **uptime** (время безотказной работы) |

> [!important] Суть DevOps
> DevOps снимает этот конфликт: изменения выпускаются часто, но небольшими порциями, автоматически проверяются и легко откатываются. Скорость и стабильность перестают противоречить друг другу.

## 2. Принципы DevOps — CALMS

| Буква | Принцип | Суть |
|---|---|---|
| **C** | **Culture** — культура | доверие, совместная ответственность разработки и эксплуатации |
| **A** | **Automation** — автоматизация | убрать рутину: всё, что можно (тесты, сборка, развёртывание, настройка), автоматизировать |
| **L** | **Lean** — бережливость | устранять потери: ручные проверки, избыточную документацию, ожидание согласований |
| **M** | **Measurement** — измерение | нельзя улучшить то, что нельзя измерить: время развёртывания, время восстановления, частота сбоев |
| **S** | **Sharing** — обмен знаниями | прозрачность процессов, общие инструменты и базы знаний для разработчиков и инженеров эксплуатации |

## 3. Жизненный цикл DevOps

```mermaid
flowchart LR
    A["Планирование"] --> B["Кодирование"]
    B --> C["Сборка"]
    C --> D["Тестирование"]
    D --> E["Релиз"]
    E --> F["Развёртывание"]
    F --> G["Эксплуатация"]
    G --> H["Мониторинг"]
    H --> A
```

| Этап | Что происходит |
|---|---|
| **Планирование** | сбор требований и заявок, анализ |
| **Кодирование** | написание кода, хранение в Git |
| **Сборка** | создание артефактов, конфигурирование дополнительных файлов для работы проекта |
| **Тестирование**¹ | автоматический прогон тестов: модульных, интеграционных, проверка качества кода |
| **Релиз**¹ | версия, прошедшая проверки, помечается как готовая к выкладке |
| **Развёртывание** (Deploy) | автоматическая установка и доставка кода, настройка приложения |
| **Эксплуатация**¹ | работа системы у пользователей: администрирование, масштабирование, резервное копирование |
| **Мониторинг** | сбор логов и метрик, оповещение об ошибках, возврат к планированию |

¹ В конспекте у этих этапов не было описания, оно добавлено.

> [!tip]
> Цикл замкнут: данные мониторинга становятся входом для нового планирования. Поэтому DevOps часто рисуют знаком бесконечности ∞.

## 4. Ключевые инструменты

| Практика | Суть | Инструменты |
|---|---|---|
| **CI/CD** | непрерывная интеграция и доставка: автоматическая сборка, тестирование и выкладка кода при каждом изменении в репозитории | GitLab CI, GitHub Actions |
| **IaC** | управление инфраструктурой через код, а не вручную; среду можно воссоздать за минуты | Puppet, Ansible¹, Terraform¹ |
| **Контейнеризация** | упаковка приложения со всеми зависимостями в лёгкий изолированный контейнер, который везде работает одинаково | Docker, Podman |
| **Оркестрация** | управление множеством контейнеров: масштабирование, восстановление при сбоях | Kubernetes (K8s), Docker Swarm |
| **Мониторинг и логирование** | сбор метрик производительности и логов для поиска причин сбоев | Grafana, Prometheus¹ |
| **Управление конфигурациями и секретами** | безопасное хранение паролей, ключей API и настроек | HashiCorp Vault |

¹ Добавлены популярные инструменты.

> [!example] Как это работает вместе
> Разработчик делает `git push` → CI собирает Docker-образ и прогоняет тесты → CD выкладывает образ в Kubernetes → Prometheus и Grafana показывают, что после выкладки ошибок не стало больше.

## Вопросы для самопроверки

> [!question]- В чём конфликт разработки и эксплуатации, который решает DevOps?
> Разработчики хотят часто выпускать изменения, эксплуатация хочет стабильности. DevOps делает частые изменения безопасными: маленькие порции, автоматические проверки, быстрый откат.

> [!question]- Расшифруйте CALMS.
> Culture, Automation, Lean, Measurement, Sharing — культура, автоматизация, бережливость, измерение, обмен знаниями.

> [!question]- Чем контейнеризация отличается от оркестрации?
> Контейнеризация упаковывает приложение с зависимостями. Оркестрация управляет множеством контейнеров: запускает, масштабирует, перезапускает при сбоях.

> [!question]- Что даёт IaC?
> Инфраструктура описана кодом, поэтому её можно хранить в Git, проверять и воссоздавать за минуты без ручной настройки.

> [!question]- Почему жизненный цикл DevOps замкнут?
> Мониторинг даёт данные об ошибках и поведении системы, и они становятся входом для следующего планирования.
